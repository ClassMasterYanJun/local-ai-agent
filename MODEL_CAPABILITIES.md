# Возможности локальной модели

## Используемая конфигурация

- **Модель:** Qwen2.5 7B Instruct
- **Формат:** GGUF, квантизация Q4_K_M
- **Движок:** портативный llama.cpp (Windows x64 CPU)
- **Контекст в пакете:** 8192 токена
- **Рекомендуемая память:** 16 ГБ ОЗУ; минимально — 8 ГБ

Модель работает полностью локально. Веб-чат отправляет запросы на OpenAI-совместимый API `llama.cpp` по адресу `http://127.0.0.1:8080/v1/`.

## Подходящие задачи

- разговор и ответы на русском и других языках;
- черновики, резюме, переводы и объяснения;
- разбор текста и структурирование информации;
- помощь с программированием, объяснение и проверка кода.

## Ограничения

- На CPU генерация может быть медленной, особенно для длинных ответов.
- Модель может ошибаться: перепроверяйте важные факты, расчёты, медицинские и юридические выводы.
- Модель не имеет доступа к интернету и не получает свежие сведения сама.
- Контекст ограничен: длинные документы лучше передавать частями.

## Профили инструкций

`train-model.ps1` создаёт JSON-профиль с системной инструкцией. Это удобный способ сохранить настройку роли ассистента, но не fine-tuning: веса GGUF остаются без изменений. Настоящее дообучение требует отдельного процесса, например LoRA в PyTorch/Transformers, а затем подготовки нового совместимого GGUF.
